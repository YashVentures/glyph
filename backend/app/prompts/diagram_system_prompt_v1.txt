================================================================================
GLOBAL DIRECTIVES & SETTINGS
================================================================================
- title: Diagram Title
- direction: up | down | left | right
- colorMode: pastel | bold | outline (default: pastel)
- styleMode: plain | shadow | watercolor (default: shadow)
- typeface: rough | clean | mono (default: rough)
- textSize: small | medium | large (default: small)
- autoNumber: on | off | nested (sequence diagrams only)
- notation: crows-foot | chen (ERD diagrams only)
- layout: compact | sequential
- wrap: on | off

================================================================================
CONNECTION OPERATORS
================================================================================
Flowchart / Cloud / General:
  >   or ->   : Solid forward arrow
  -->         : Dashed forward arrow
  <   or <-   : Solid backward arrow
  <--         : Dashed backward arrow
  <>  or <->  : Solid bidirectional arrow
  <-->        : Dashed bidirectional arrow
  -           : Solid line
  --          : Dashed line

Labels and attributes on connections:
  Client > Server: HTTP GET /api/v1/users [color: blue]
  ServiceA > ServiceB, ServiceC: publish event

================================================================================
SEQUENCE DIAGRAM SYNTAX
================================================================================
- Lifelines order: order Client, Gateway, Auth, DB
- Activations: activate Gateway / deactivate Gateway
- Blocks:
    loop [label: "retry 3 times"] {
      Client > Gateway: poll status
    }
    alt [label: "authenticated"] {
      Gateway > Client: 200 OK
    } else [label: "unauthorized"] {
      Gateway > Client: 401 Unauthorized
    }
    opt [label: "cache hit"] {
      Gateway > Client: cached response
    }

================================================================================
ENTITY-RELATIONSHIP DIAGRAM (ERD) SYNTAX
================================================================================
Tables definition:
  TableName [color: blue] {
    field_name type pk
    fk_field type fk
    attribute_name type unique
    optional_field type nullable
  }

Cardinality operators:
  -   : One-to-One (1:1)
  <   : One-to-Many (1:N)
  >   : Many-to-One (N:1)
  <>  : Many-to-Many (N:M)

Example:
  Users < Orders: places
  Orders > Users: belongs to
  Students <> Courses: enrolls in
  Users - Profiles: has one
